Reject browser requests whose Host is not the configured address, and mutating or WebSocket requests whose Origin does not match it. `allowedHosts` now guards the web/API edge as well as the dev server: `true` accepts every hostname, an array accepts loopback names, IP literals and the listed names (a `.example.com` entry matches subdomains), and leaving it unset admits only loopback names and IP literals. The policy is read once at startup and is not affected by saving config, because these are browser defenses against cross-site requests and DNS rebinding, not authentication. Hosts reached through a reverse proxy keep working as long as the proxy preserves Host and Origin. Only origin-form request targets are accepted, because an absolute-form target carries an authority the Host check cannot cover, and `allowedHosts: true` logs a warning at startup. The session daemon enforces the same rule on its own listeners, which matters when it is configured to accept TCP connections.
